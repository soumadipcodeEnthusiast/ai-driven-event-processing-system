# GrafanaDown

| | |
|---|---|
| **Alert** | `GrafanaDown` |
| **Severity** | warning |
| **Service** | grafana |
| **Rule file** | `infra/prometheus/rules/aiops-alerts.yml` |
| **Dashboards** | [Service Health](http://localhost:9030/d/aiops-service-health) · [SLOs](http://localhost:9030/d/aiops-slo) |

Grafana (the REQ-034 dashboard) has not been scrapeable for 5 min.

## Symptoms

http://localhost:9030 does not load; `up{job="grafana"} == 0`.

## Impact

Operators cannot see the Service Health dashboard (REQ-034). Alerting itself (Prometheus rules, forecasting) keeps working; alerts remain available via `GET :8081/alerts`.

## Diagnosis

```bash
docker compose -f infra/docker-compose.yml ps grafana
docker compose -f infra/docker-compose.yml logs --tail=200 grafana     # provisioning errors
curl -fsS localhost:9030/api/health
```
Common causes: invalid provisioning YAML under
`infra/grafana/provisioning/`, broken dashboard JSON under `infra/grafana/dashboards/`.

## Mitigation

1. `docker compose -f infra/docker-compose.yml restart grafana`.
2. Provisioning error → validate files: `python3 -m json.tool infra/grafana/dashboards/*.json`, fix, restart (dashboards are generated by `infra/grafana/gen_dashboards.py`, so prefer fixing the generator and regenerating).
3. Meanwhile, read alerts directly: `curl -s localhost:9081/alerts | jq`.

## Escalation

1. Service owner (see table in [README](README.md#ownership)).
2. If not acknowledged within 15 min for `critical`, escalate to the DevOps Engineer on-call.
3. If customer-visible for > 30 min, declare an incident (SEV-2) and open a postmortem.
