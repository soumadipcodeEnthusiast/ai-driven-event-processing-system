Guided demo

Work left to right. The blue box under each step is what to say.

“Applications publish JSON events into Kafka. I'll send a batch with some broken on purpose, so you can see validation and the dead-letter topic at work.”

Watch the event flow above: the counters and links react within two seconds.

“These are the real messages on each topic. Valid events come out normalised; rejected ones go to the DLT with the reason in a header. Anomalies and AI playbooks are topics too.”

Read straight from the broker, newest first.

“The diagnostic service learns what normal looks like for each service. A checkout request usually takes about 100 ms. Watch what a slow one scores.”

Each run trains a fresh baseline of 30 normal requests (about 100 ms ± 12), then scores yours. Try 140 ms at threshold 0.8, then switch to 0.6 and score again.

Threshold, changed live

“When something looks wrong, GraphRAG works out why. It pulls the component's two-hop neighbourhood from Neo4j, hands it to a local LLM, and gets back a ranked remediation playbook.”

If you scored an anomaly in step 3, it is passed along as evidence. The local model on CPU takes 20–90 s; the rule-based fallback answers instantly if the LLM is unavailable.

“Instead of waiting for something to break, a Temporal Fusion Transformer trained on this platform's own metrics forecasts the next hour, and raises an alert while there's still time to act. Every alert gets a GraphRAG playbook too.”

“Simulate” lowers one threshold below the current value, forecasts, then restores it.

“Both topics are batched into compressed files in S3, partitioned by date and hour, for replay and audit.”
